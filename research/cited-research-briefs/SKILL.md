# Cited Research Briefs (MCP fleet + citation ledger)

Produces ledger-verified, cited briefs — the deliverable the portfolio audit pipeline expects from research subagent waves (files land in `/home/<user>/portfolio_audit/research/research-<X>-<topic>.md`, siblings `research-A-selection.md`, `research-B-risk.md`, `research-C-methodology.md`).

Companion skills (load them; they are the deep references): `grounded-citations` (ledger mechanics), `search-engine-routing` (engine mix), plus the domain umbrella. If those skills are user-owned and you may not edit them, this skill carries the workflow and pitfalls that are NOT documented in them.

## Pipeline
1. Reset the citation ledger: `sources.py reset`. Register EVERY URL at retrieval time (`sources.py add <url> --title "..."`) — idempotent, stable ids, kills hallucinated-URL risk at write time. CLI mechanics (hit in production Aug 27 2026): `--ledger <path>` goes BEFORE the subcommand (`sources.py --ledger L reset`, NOT `sources.py reset --ledger L` — the latter dies with "unrecognized arguments"), and `add` accepts ONE url per invocation: a `--title` after the first URL makes argparse reject every trailing positional. Register a batch as a shell loop, one `add` per URL with its own `--title`, then `list | tail` to confirm ids.
2. Engine mix (measured Aug 2026): Exa + Parallel = best diversity pair; Brave = cheap third index; Firecrawl search = extraction-only (10 req/min cap) — use `firecrawl_scrape` / `web_fetch_exa` to READ promising pages. Exa query style: describe the ideal page, not keywords. Register sources as results arrive, in one `add` per URL; keep a deterministic add order so ids stay stable.
3. Verify uncertain sources BEFORE citing: fetch the page (web_fetch_exa / firecrawl_scrape) to confirm authors/title/URL — working-paper PDFs (e.g. the Yale "Re-Standardized Financial Statement Data" PDF → Lyle-Siano-Yohn 2024) and preprint records (Zenodo screen audit → Brina 2026) routinely need attribution checks. If a search returns only a different paper than expected, DROP the citation — never cite unverified.
4. Write the draft with inline `[n]` after each sentence, max 3 ids per sentence, one sentence per line — from the FIRST pass. Multi-sentence paragraphs typed on one line trip the >3-per-line check and silently depress coverage; fixing it later means rewriting the whole file (happened twice on research-E: 23% → 55% coverage).
5. Iterate `sources.py verify draft.md` until clean (exit 0, no warnings).

## Pitfalls (all hit in production Aug 26-27 2026)
- **`render --replace-in` writes only CURRENTLY-CITED sources.** Citing a source that was uncited at the last render makes verify fail with "cited but absent from the Sources block" until you re-render. Sequence: finish ALL inline citations, THEN render + verify.
- **The ">3 citations per sentence" check counts per sentence FRAGMENT, not per line.** sources.py splits each prose line on `(?<=[.!?])\s+` and flags any fragment carrying 4+ bracket groups — so a dense one-line paragraph with groups spread across clauses (`...[6]; the beneficial version is ... [5][9][26]`) still trips it. Fixes that actually work: (1) split dense (a)-paragraphs at sentence boundaries — single newlines render identically in markdown; (2) split `; ` clauses that accumulate groups (turn `...overconfidence [6]; the beneficial version...` into two sentences); (3) rebalance groups so every fragment is ≤3 (e.g. `[8][5][7] ... [1][13]` → two sentences). Re-run verify until the warning disappears; the stats line counts sentences, not lines.
- **PDF reads: `web_fetch_exa` can fail on working-paper PDFs (CRAWL_UNKNOWN_ERROR).** Fall back to `firecrawl_scrape` with `formats:["markdown"]`, `parsers:["pdf"]`, `maxAge:0` — returns full text plus page metadata (title/authors/date) that doubles as the attribution check (verified Aug 27 2026 on a Bayes Business School PDF).
- **Duplicate-record warnings are harmless but avoid them:** registering the same work via ResearchGate AND the original PDF produces "registered in the ledger but not cited" warnings at verify. Register one canonical URL per work; if you already duplicated, leave it — verify still exits 0.
- **Coverage counts prose sentences** — internal findings, table rows, headers count as prose but should NOT be cited. Realistic target for a brief with internal quotes: ~50%, reached by citing verdict/nuance sentences that restate evidence, never by padding findings. Run verify without a threshold first to read the stats line.
- **`sources.py` has no delete.** A typo'd URL is fixed by `reset` + re-adding all entries in one script (deterministic order keeps ids stable).
- A search snippet supports only what it literally says — fetch the page before citing body claims.
- **Author-index attribution trap.** Author archive pages, "recommended for you" sidebars and search snippets interleave other writers' pieces, so a title that surfaced under person X's author page can be person Y's. Verified Aug 2026: "Conservatives are losing more than elections" (thehub.ca, 21 Aug 2026) surfaced under Ginny Roth's author page and is Sean Speer's byline. Confirm the byline on the article page before attributing any quote or position to a person.
- **Oversized tool payloads are already on disk — mine them, never re-request.** Parallel `web_search` and large Exa searches exceed the 50KB tool-output cap and persist to `/home/<user>/.hermes/cache/spillover/call_*.txt`. Read them in execute_code with regex extraction (`re.finditer(r'"url": "([^"]+)"', txt)` for the source list, then keyword windows of ±350 chars) rather than paging the file into context or re-running the search. This turns a 57KB payload into a few hundred bytes of the parts that matter.
- **A quantitative claim deserves a computed number, not a cited snippet.** When the domain has an operator-published raw dump or API (fan/community stats sites, exchanges, registries), compute the statistic yourself and cite dataset URL + date range + N; forum-quoted percentages are routinely impossible on their face. Workflow, confound checklist, and the urllib-403 / SPA-extraction pitfalls live in `open-data-claim-verification`.
- **Exa search output is page content, not a snippet.** `web_search_exa` returns real page excerpts (abstracts, body text), so most citations verified directly from search output with ~zero fetches (research-E: 33 sources, no per-source fetches needed). Reserve `web_fetch_exa` / `firecrawl_scrape` for thin excerpts (paywalled ScienceDirect abstracts) and load-bearing claims. Brave/parallel descriptions stay snippet-grade — fetch before citing those.
- **Conflated numbers across sources.** When two sources carry similar figures for different windows, drafts silently merge them (research-E nearly wrote "bonds fell ~12% in 2022's first nine months" by fusing QuantPedia's -12.63% bond bear market Aug 2020–Mar 2022 with Man Group's "worst bond drawdown in two centuries" for 2022 YTD). Before writing any figure, re-read it in the source text; run a self-review pass on every number.
- **Register each search batch before launching the next one.** In research-H, four searches (Barberis-Huang, Korniotis-Kumar, QMJ, MSCI Foundations) were run and their content reviewed, but the `add` step was deferred until after two more search batches — verify then failed with "citations not in the ledger: [18], [19], [20], [21]". Recovery is clean: `add` the missed URLs in the same order the draft cites them (ids land on the exact numbers already written), re-render, re-verify. Late registration is safe only because `add` is idempotent AND the add order matches the draft's id order.
- **Ids are ledger-local — a sibling ledger's id is not this ledger's id.** Kumar (2009) was [11] in ledger-G, but in ledger-H [11] is the EDHEC characteristics-index paper; a draft sentence citing "[18][11]" for lottery preferences silently pointed at the wrong work. When a claim is carried by a source registered in another brief, write "(mapped in research-G [10])" and attach NO bracket id, or attach the id of a fresh source that independently supports the claim — never pad by-file sentences with a fresh id to lift coverage, and re-check every bracket against the CURRENT ledger before rendering.
- **One ledger per research file in the portfolio pipeline.** Sibling subagents produce research-D/E/F concurrently; give each file its own ledger (`export HERMES_CITATION_LEDGER=.../ledger-<X>.json` before every sources.py call — verified working with ledger-E/F.json side by side). The env var also sidesteps the `--ledger`-position pitfall above. A shared ledger would collide ids across sibling renders; grounded-citations' shared-ledger advice targets merged drafts, not this standalone-files pipeline.

## Deliverable shape that worked
Per conclusion: (a) program finding quoted in one line, (b) literature summary 2-4 sentences, (c) 2-4 full citations (authors, year, title, journal/source, URL), (d) verdict SUPPORTED/MIXED/CONTRADICTED/NO DIRECT LITERATURE, (e) nuances. Verdict table at top, cross-cutting takeaways at bottom, rendered Sources block at end. Verified via the grounded-citations ledger before delivery.
